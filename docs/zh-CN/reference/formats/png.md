# 可执行图片容器（0.9；语言与编码 0.8）

[中文](png.md) · [English](../../../en/reference/formats/png.md) · [文档首页](../../README.md)

交付物是 RGBA PNG，读取依赖精确像素，不含渲染文本。PNG 附加块不承载源码、AST、字节码或依赖。
可见主体保存入口及所有可达模块的真实空间 token 网格。

## 物理容器

前部 RGB 字节为 `PXIMG\x08\r\n`，随后三个大端 uint32：压缩头长度、展开长度、压缩载荷 CRC32，共 20 字节。
后续 RGB 存 zlib 压缩 JSON，描述格式/版本、scale、画布尺寸、入口、模块位置；头部像素均不透明。
这是物理像素数据，不是 PNG 文本块。

头包含模块模式但排除像素与递归 bundle：版本、尺寸、连接和可选文件名/符号名/导入名/文本范围注解。
不嵌入完整文本或可执行文件。名称帮助恢复可读源码，ID 和主体 token 决定执行；连接与区域决定结构。
模块位置显式且互不重叠，留三个 tile 的边距。编码器比较确定性横向分层与竖直堆叠，选择较小画布；
解码使用记录的坐标。每块内部 `scale - 2` 的正方形颜色一致，scale 为 4..24 的整数。
类别 R 映射到可逆亮色调色板，G/B 依 `pixellang/picture.py` 的固定类别掩码 XOR。
空单元为 `(16,20,24,255)`，调色板与逻辑坐标可恢复精确网格。

验证尺寸、头大小/CRC、放置、无重叠、内部均匀颜色、token 和源码模式。
限制为 3200 万物理像素、100 万逻辑单元、16 MB 头、128 模块。
CRC 检查头损坏，不证明真实性；把整块改成另一合法颜色会成为语义可能不同的新程序。
禁止缩放、色彩校正、截图转换或 JPEG。去掉附加块后，以完全相同 RGBA 重存仍可执行。
依赖模块已包含，运行输入另行提供。

## 语言编码

源码 language/encoding/format 与 VM/IR 为 0.8，不支持的语言版本拒绝。
R=18 为 int64 头（载荷零）及四个 R=112 的 uint16；R=19 为 UTF-8 长度及延续字，奇数字节尾补零；
R=112 的 G/B 为大端数据，R=128 是 `typesys.BUILTINS` 的确定性索引。
类型和标点包含 string、unit 和类型化数组分隔符。do 丢弃表达式值；数组、下标、内建调用、unit 返回
降低为 ARRAY、INDEX、INDEX_SET、BUILTIN、CONCAT 等受检查操作。

## 往返

`pixelpack main.pxl -o program.png` 解析项目并导出图片。
`pixelrun program.png` 重建空间模块并走正常编译流程。
`pixelunpack program.png -o directory` 将空间 AST 打印为规范且带名称的多文件 `.pxl` 项目。
注释和原排版不恢复。像素中的入口标记恢复 main，不插入模块顶层调用。

## 有界连接头

写入版本 0.9 保留 `PXIMG\x08\r\n` 前缀及语义像素 0.8。
每模块 spatial.links 为空，linkChunks 是小写十六进制字符串数组；每块承载最多 512 个连接的
zlib 压缩 UTF-8 JSON，保持原顺序和模式。
每模块最多 1,000,000 条连接、1,954 块；块展开最多 100,000 字节，十六进制最多 200,000 字符。
拒绝空块、非法 hex/zlib/JSON、压缩尾随数据以及同时提供内联和分块连接。
空连接使用空块数组，普通 JSON 节点/字符串限制不变；块准备一次供布局复用。
读取器也支持容器 0.8 的内联连接；0.9 必须提供分块。这不改变语义源码或 bundle 语言版本。
