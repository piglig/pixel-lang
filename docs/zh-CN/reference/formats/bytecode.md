## 程序结构

VM 验证并复制 PIXELVM 可执行文件，language 和 VM 版本轴都须为 0.9；compiler 版本仅为信息。
文件包含常量、名义记录模式（含受验证的内建 Error）、具体枚举模式、入口，以及带参数与捕获单元签名的函数体。

机器状态包含调用帧（PC、内存、操作数基址）、共享操作数栈、类型化堆引用、常量、输出、指令数及停止/错误状态。
入口为唯一无参数 unit 函数。返回校验结果并丢弃当前帧剩余操作数，unit 使用内部哨兵值；嵌套调用不能弹出调用者的操作数。
堆包含数组、映射、记录、枚举载荷、函数环境与只读捕获单元；json 不可变并带标签。

指令包括 PUSH、LOAD、STORE、BIND、CAPTURE_VALUE、ACCESS；受检查算术/比较/逻辑；DUP/DUP2/POP/PRINT；
CALL/FUNCTION/CLOSURE/INVOKE/RETURN；STACK_DEPTH/UNWIND；JUMP/JUMP_IF_FALSE/JUMP_IF_TRUE/TRAP；
ARRAY/MAP/RECORD、ENUM/ENUM_IS/ENUM_GET、INDEX/INDEX_SET、FIELD/FIELD_SET；BUILTIN；
VALUE_SET/VALUE_CHECK/VALUE_COLLECTION；显式单/双模式 ITER_SNAPSHOT；
RESULT_BUILTIN/RESULT_DECODE 与 PROPAGATE。
操作数验证与动态行为见 `pixellang/vm.py`；原生指令生成见
`selfhost/ir_expr.pxl` 及其 IR 模块。

静态解析到无捕获声明的调用使用 `CALL`，参数从左到右求值。
动态调用先计算被调用值，再计算参数，使用 `INVOKE`。两条路径都检查参数类型、
访问模式、调用深度和目标的效果契约。函数类型为 `fn(T)->(R)` 或
`effect_fn(T)->(R)`，由 `effectFunctions` 决定。

闭包通过 `CAPTURE_VALUE` 捕获只读值；之后重新赋值外层绑定不会改变已捕获的值。
不可变载荷可以共享存储，捕获不能用于修改外层绑定。显式 `inout` 参数提供临时
写入访问，详见下文。

验证拒绝未知版本/操作码、畸形模式/常量、无效槽/常量/跳转、未知调用与非法入口签名。
运行时检查类型、未初始化内存、帧边界、整数溢出与预算。
外部字节码并不因此获得完整静态安全证明；非法执行产生结构化诊断，不作为宿主代码执行。
GC 从帧、操作数栈和临时分配根标记后清扫，确定性身份与完整检查点支持跨 GC 回放。
预算与错误见[运行时](runtime.md)。

## 原生空间与数据流

可执行文件另外保存 `coordinateFrames`（名义坐标系到长度单位）、
`effectFunctions`（允许外部效果的函数身份）和 `flows`（有类型的图与状态元数据）。
这些字段由自举编译器产生，VM 在运行前验证；渲染器不参与解释。

| 指令 | 语义 |
| --- | --- |
| `SPATIAL_VALUE` | 用 x/y/z 构造带坐标系的 Point3 或 Vec3 |
| `SPATIAL_BINARY` | 受检查的位置／位移运算与比较 |
| `SPATIAL_TRANSFORM` | 构造显式坐标变换，检查旋转矩阵与目标坐标系平移 |
| `SPACE_NEW` | 创建具有运行时唯一身份的不可变空间快照 |
| `SPACE_OP` | 执行空间、实体、类型化连接及变换操作 |
| `FLOW_NEW` | 创建声明对应的独立状态实例 |
| `FLOW_STEP` | 以有类型输入推进实例，在成功时原子提交 |
| `FLOW_CONFIG` | 读取当前实例路径的只读创建参数；操作数是创建参数索引 |
| `FLOW_READ` | 读取当前步骤的旧状态单元 |
| `FLOW_STAGE` | 暂存下一状态，等待步骤提交 |

图按检查后的拓扑降低为函数、调用和槽操作。`flows` 元数据与实际指令
交叉验证，保留命名表达式、状态、来源范围与持久子实例关系；运行时不会将图
元数据重新解释为可执行接线。状态化 flow 必须通过显式实例推进。失败丢弃包括嵌套
实例在内的待提交状态。运行时也检查输入只读及 flow 的纯执行契约。

Point3、Vec3、EntityId、LinkId、Entity、Space、Link 为原生运行值。实体和连接载荷在快照边界
隔离；提取的容器采用值语义，后续更新不改变已发布快照。空间身份、分配预算和
flow 状态进入完整检查点。
坐标的源码来源只服务于调试，不参与相等、哈希或数值计算。详细契约见
[原生空间](../../internals/spatial-model.md)和[原生数据流](../../internals/dataflow.md)。

## 类型化映射

运行时接受规范类型 `map<K,V>`，键和值的类型均保持不变性。
标量、枚举、Point3、Vec3、EntityId 和 LinkId 按有界的结构值判定键身份；容器和可执行值不能作键。
迭代保持插入顺序，替换值不改变位置，删除后重新插入则排在末尾。
构造时遇到重复键抛出 `collection.duplicate_key`。

调试堆快照使用有序的 `{key, value}` 条目。JSON 对字符串键使用对象，
对其他键类型使用条目数组。空间和 flow 快照同时冻结键和值；持久化检查点
保存逻辑值，不保存堆地址或缓存的哈希标记。恢复时验证键类型及重复项，
恢复时重新构造查找身份。键参与垃圾回收、快照复制和空间分配计数。

映射使用 `map[K, V]`；前端拒绝单参数写法。
MAP 指令使用双参数类型；旧 Python 编译前端已删除。

## 实例初始化参数

`flows[id].initialInputs` 描述仅在实例创建时使用的参数，每项包含 name、node、slot、type。
它与每步 inputs 使用独立参数槽和名称作用域；源码节点身份不能冲突，初始化参数在每步计算中不可见。
`FLOW_NEW id` 按该签名从栈中取参数，检查类型，并冻结调用方数据。
每个状态 initializer 函数接收所属 flow 的完整初始化参数，返回该状态的声明类型。

子 flow 节点的 `initializers` 按子实例参数顺序列出初始化函数。每个函数接收父实例的
初始化参数并返回一个子参数；参数全部求值后才初始化子状态。无参数声明省略或使用空列表。
有初始化参数的图及包含它的父图必须通过显式实例运行，即使它没有直接声明状态。
这些函数由原生 VM 执行，不通过宿主解释表达式或生成临时源码。

初始化参数沿用不可变状态的数据限制。每次初始化调用都获得独立的只读参数视图，
调用方后续修改不会影响初值。初始化函数不得执行 I/O、调用任意函数或推进其他实例；
子参数初始化还不能分配空间身份。空间创建仍属于具体状态初始化，并按实例路径隔离。

只有根实例及所有子实例初始化成功后才发布句柄。错误或取消丢弃全部未发布状态，
恢复空间身份集合和原生分配预算。完整调试检查点保存初始化任务、参数值与执行游标，
可从中途确定性继续。创建完成后释放临时参数快照；持久化应用检查点仍只保存已提交状态。

自举编译器已从独立的创建参数列表生成该描述，并覆盖类型检查、原生 IR、PNG 往返、
源码恢复与图投影。参见[创建参数指南](../../guides/state-machines.md#创建时参数与每步输入)。
运行时与源码专项测试分别见 `tests/test_flow_initial_arguments.py` 和 `tests/test_native_flow_constructors.py`。

## 值与受检查转换

普通数据采用值语义。可写绑定允许替换根值；路径写入构造更新后的值，不改变已有快照。
`FREEZE`、`THAW` 和带可变限定的数据类型不再接受。受检查的解码、解压通过
`RESULT_DECODE`、`RESULT_BUILTIN` 返回原生 Result；原始 `JSON_DECODE` 和
`ZLIB_DECOMPRESS` 指令被拒绝。

## 值路径写入

`VALUE_SET` 实现值语义赋值，随附开发编译器已用于普通 var 赋值。操作数是长度
1..128 的路径：`{"field": "name"}` 表示记录字段，`{"index": true}` 表示动态下标。
栈顺序为基值、依次求值的动态下标、替换值；指令弹出这些值并压入更新后的根值。
它不写入旧对象，只复制路径上的记录、数组或映射，其他不可变子树继续共享。
映射末端下标允许插入；中间键必须存在，数组下标必须在范围内。
类型错误、路径错误、取消和分配预算失败均不得修改原值，临时 GC 根会被释放。
编译器检查源码左值权限并保留地址求值顺序；独占访问使用下文的 ACCESS。
`VALUE_CHECK` 使用相同路径操作数，弹出基值和动态下标，不压入结果。它在右侧
表达式之前检查末端写入位置；中间路径先按顺序读取，失败会阻止后续下标求值。
这些指令本身不授予修改 let 绑定的权限。

`VALUE_COLLECTION` 的操作数包含 `method` 与 `result`。当前方法为数组
`append`、`extend`、`pop` 及映射 `remove`。栈输入为接收者和方法实参；
输出依次为更新后的接收者及方法结果。append/extend 的结果为 unit，
pop/remove 的结果为元素类型对应的 Option；空数组或缺失键返回 None。
接收者始终保持不变，编译器只有在结果完整生成后才写回可写根。
普通映射 `get` 使用已有的只读查询指令，返回 Option，不进行写回。
嵌套写入遵循下文的根绑定独占访问规则。

`CAPTURE_VALUE` 是语言重设计中只读值捕获的运行时基础。操作数为局部槽位或
`{slot, type}`。它读取绑定当前值，压入新建的只读捕获单元，不装箱或替换外层绑定。
不可变负载可以共享存储；显式可变值被拒绝。STORE 不能修改该单元，检查点恢复后
仍保留这一限制。随附开发编译器已生成只读捕获，原生源码与编辑器验收覆盖了
外层绑定后续写入不影响捕获值的行为。

### inout 访问

函数参数使用内部签名 `inout<T>` 保存访问模式；它不能出现在字段、元素、捕获或返回值中。
函数值类型可以包含该参数模式，如 `fn(inout<int>)->(unit)`，访问模式必须精确匹配。

`ACCESS` 操作数为 `{slot, type, path}`。`slot` 指向当前帧的根绑定，`type` 是位置的声明值类型，
`path` 使用 VALUE_SET 的字段／下标选择器，可为空。动态下标按路径顺序压栈，指令消费下标，
验证地址后压入临时访问令牌。CALL／INVOKE 只将令牌传给匹配的 inout 参数，并在进入调用时
接管其生命周期。LOAD 读取普通值，STORE 通过持久值更新机制写回调用者，不能把令牌存成普通值。

当前采用整个根绑定的独占访问；嵌套借用暂时暂停父访问。准备后续普通实参时仍可读取待借用值。
单次写回完成验证与分配后才发布；失败保留旧根。普通函数此前已完成的修改不会自动回滚，
这与 flow 整步原子提交不同。返回、异常和取消释放访问权限；检查点保留作用域与根绑定关系。
原生源码和 PNG 的候选验收状态见[设计原则](../../internals/design.md)。

### 函数效果

新编译器输出 `effectFunctions: [函数标识]`，清单中的函数允许外部效果，其他函数
均按纯函数执行。函数值的内部类型分别为 `fn(...)->(...)` 和
`effect_fn(...)->(...)`；后者在源码中显示为 `effect fn(...)`。
纯函数可以满足允许效果的回调契约，反向赋值禁止。

调用边界按被调用函数的声明检查权限：纯调用者不能调用有外部效果的函数，
即使被调用者为空实现。允许效果的调用者也不会把权限传给纯被调用者。
纯函数执行 I/O 或创建、推进运行实例时属于执行故障。`inout` 是独立的参数
访问权限，不自动授予外部效果。流程节点及初始化函数保持纯契约。

`effectFunctions` 是必需字段。旧 `componentFunctions` 元数据（包括空清单）和
`component(...)` 函数类型均被拒绝；运行时没有旧组件隔离或捕获复制分支。
源码编译、PNG 往返和恢复后的重编译已验证，发布验证见[分层验证](../../contributing/verification.md)。

## 表达式 flow 字节码

编译器以普通表达式指令实现 flow，并保留状态与提交边界。
`flows[id]` 的 `values` 保存命名计算及其表达式节点、槽位和类型；`children` 保存持久子实例的
声明身份、目标函数及构造参数初始化函数。`dependencies` 保存声明／使用位置的依赖关系，
`order` 只排列命名计算，`updates` 标识状态提交表达式，`output` 标识结果节点和槽位。
旧 `nodes`／`connections` 接线元数据不再接受。

`FLOW_CHILD_STEP {node, reference}` 的 node 是所属 flow 的子实例声明 ID，reference 是源码中的
接收者引用位置。目标函数从已验证的 children 声明取得；运行路径由父路径追加声明 ID 构成，
不使用调用表达式的位置推断持久身份。普通 CALL 不能调用有状态 flow。
子实例每步最多推进一次；互斥分支可以包含不同调用位置，未推进的子实例保持旧状态。
所有实际参与实例的更新在父步骤成功后统一发布；检查点保存参与路径和暂存更新。
未出现在 `updates` 中的状态保留已提交值；每个声明的更新仍须恰好执行一次。验证器将
FLOW_STAGE 与声明的更新子集核对，不生成隐式自赋值。

验证器核对声明、槽位、状态读写、计算存储顺序、子实例目标、初始化权限与返回位置。
元数据用于类型及调试来源校验，不重新解释为另一套可执行接线程序。
开发验收覆盖原生执行、字节码边界、程序 PNG 恢复与 Studio 图编辑；发布要求见[分层验证](../../contributing/verification.md)。

## 显式结果传播

开发运行时要求原生 `Result<T,E>` 的模式严格为 `Ok {value:T}`／`Err {error:E}`，
原生 `Option<T>` 则为 `Some {value:T}`／`None {}`。普通枚举不能通过声明同名
变体来获得传播能力。

`PROPAGATE {source, target}` 检查一次栈顶操作数。成功时用负载替换栈顶；
失败时以当前函数的结果类型返回 Err 或 None，仅丢弃当前帧尚未完成的操作数，
并执行正常返回清理。两种类型必须属于同一原生类型族，Result 的错误类型须
完全一致，成功负载类型可以不同。target 必须等于当前函数声明的返回类型。

传播不能越过闭包边界，也不能直接从 flow 返回。它会释放尚未完成的 inout
访问，保留此前已经写入的修改，不抛出可恢复异常，也不隐式回滚业务状态。
源码、PNG 与运行时均须遵循同一传播契约。

## 受检查数据操作

`RESULT_BUILTIN {name, result}` 调用受检查的数据／I/O 内建操作，返回 result 指定的
原生 `Result<Success,Error>`。名称必须来自受检查操作表，参数数量和成功类型必须
与该操作匹配。`RESULT_DECODE {result}` 消耗一个 JSON 文本字符串，成功类型指定
具体解码目标。两条指令都要求精确的原生 Result 变体结构。

操作与结果分配完成前，实参始终保留为 GC 根。预期数据失败转换为 Err；取消、资源
耗尽、无效操作数和效果违规仍是执行故障。结果包装分配位于数据错误捕获边界之外。
这些指令不会自动回滚此前的 I/O 或 inout 写入。

随附开发编译器已生成上述指令。旧 `TRY`、`END_TRY`、`JSON_DECODE`、
`ZLIB_DECOMPRESS` 以及绕过受检查原语的普通调用均被拒绝。

## 表达式退出时的操作数清理

`STACK_DEPTH` 将当前帧基址以上的操作数数量压栈。编译器在进入循环时把该标记保存到
临时局部槽。`UNWIND slot` 读取该槽，在循环退出跳转前丢弃保存深度以上的操作数。
标记必须是零到当前帧操作数数量之间的整数，不能删除调用者的操作数。标记使用普通局部槽，
可随检查点保存和恢复，无需额外隐藏栈。

清理只释放被丢弃部分中的待调用 inout 参数借用，保留外侧实参和正在使用的形参。
同一访问令牌横跨保留与丢弃边界的重复引用会被拒绝。`RETURN` 丢弃当前帧待完成的操作数，
释放该帧的访问权限，保留已经完成的写入；这些操作不回滚状态。
值块内的局部循环使用相同清理机制，保留外侧表达式的操作数。`?` 传播失败时执行帧级清理。
值块不能通过 return 或 break／continue 跳出到外层上下文。
