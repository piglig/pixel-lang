## 规则与接口

A=0 表示空单元，A=255 表示语义单元；部分透明和未知颜色报错。
载荷 N=256*G+B 根据类别解释，不直接作为 VM 操作码。

| R | 含义 |
| --- | --- |
| 16 | 有符号 16 位字面量 |
| 17 | 布尔载荷 0/1 |
| 18 | int64 头，后接四个大端数据字 |
| 19 | UTF-8 字节长度，后接大端字节对 |
| 20 | 有限 binary64 头，后接四个大端数据字 |
| 32 | 无符号 16 位标识符 |
| 48 | 操作符表索引 |
| 64 | 关键字表索引 |
| 80 | 标点表索引 |
| 96 | 类型表索引 |
| 112 | 16 位字面量延续字 |
| 128 | 内建操作表索引 |

当前表为 `pixellang/codec.py` 的 OPS/KEYWORDS/PUNCT/TYPES 和 `pixellang/typesys.py` 的 BUILTINS。
解析器重建字面量并验证 UTF-8、长度和整数头。var 与 entry 是可执行关键字。
双绑定 for 用逗号，jsonDecode 携带目标类型。

language/encoding/file 版本轴均为 0.9，其他版本拒绝。
`picture.py` 的显示调色变换无损可逆，与语义 RGBA 分离；精确坐标和关系边仍参与语义。
泛型参数与实参、枚举与构造器、穷尽 match、匿名函数体引用均为可执行 token。
匿名函数体存于独立空间区域并重建词法 AST，从体内推导捕获。见[函数](../language/functions.md)、[枚举](../language/enums.md)。

## 当前原生模型编码

本节描述当前编译器采用的表达式 flow 编码。
`pixellang/codec.py` 的物理令牌表必须与 `selfhost/pixel_tokens.pxl` 一致。
宿主只解释物理颜色，解析、类型检查和恢复由 PixelLang 编译器负责。
程序语义不依赖图片元数据中的源码文本或可读名称。

`frame` 保存坐标系的名义身份与长度单位。Point3、Vec3、Transform3、Entity、Space、
Link 和 Flow 的类型参数按完整类型编码；导入坐标系保留模块与声明身份。
XYZ 是空间坐标，不隐含逻辑时间。

### 表达式 flow 区域

`flow` 头部保存声明身份、创建参数、每步参数及返回类型。
子区域直接恢复为以下原生 AST，不经过端口接线或文本展开：

| 区域关键字 | 保存的内容 | AST |
| --- | --- | --- |
| let | 绑定身份、类型与普通表达式 | flow_value |
| state | 绑定身份、类型与初值表达式 | flow_state |
| instance | 绑定身份与直接构造调用 | flow_instance |
| next | 状态绑定身份与普通表达式 | flow_next |
| output | 普通表达式 | flow_output |

命名计算、状态与子实例使用普通词法绑定身份，不再保留单独的图局部身份区间。
子实例的 `.step(...)` 使用普通字段和调用编码；恢复后的检查器重新验证其所有者、
参数、推进次数和实例依赖。依赖图从绑定后的表达式重新建立，不依赖附加图元数据。
发射器为推导出的状态与命名值写入确定的类型；解析器也接受省略类型的像素声明。
可选名称信息仅改善显示；去除它后，标识符身份仍须足以完成恢复和重新检查。

删除 `node`、`connect` 令牌及其解析路径；flow 外的 state、instance、next、output
在解析阶段拒绝。普通函数内的 let 仍恢复为普通局部声明。

### 函数与访问权限

函数统一为 fn。`effect_fn`、`effect_function` 与 `effect_body` 分别保存
有外部效果的声明、函数类型与独立匿名函数体；恢复为 `effect fn`。
普通函数和有外部效果的函数共享参数、返回值与闭包结构。
捕获关系从恢复后的词法绑定推导，图片不保存运行时捕获值。
旧 component 声明和函数类型已删除。

普通记录、容器和枚举按值类型编码；不再存在 mut、Frozen、freeze 或 thaw 的内建令牌。
`inout` 使用类型索引 25（`[96, 0, 25, 255]`），后接括号包围的值类型，
仅参数声明和函数类型参数允许使用。调用前的 `&` 使用标点索引 18，后接写回路径。
恢复源码保留这两个标记，并重新执行原生访问、类型和独占检查。

### 声明契约与记录更新

泛型参数身份后的 `:` 与 Equatable、Ordered、Numeric、Hashable 类型标记保存能力约束，
恢复为 type_constraint，由类型检查器验证；它们不是普通值类型。

`with` 使用关键字索引 35。表达式先编码括号包围的基值，再编码 `with {`、
按源码顺序排列的 UTF-8 字段名和替换表达式，最后为 `}`。
解码产生原生 record_update 节点；简写字段保存其已绑定表达式，未指定字段由基值保留。

## 值块编码

表达式中的 `value_block(id)` 引用同一模块的 `value_body id` 根区域。
块体仍由普通语句子区域组成，末尾结果使用 `block_result` 子区域；它必须位于块体最后。
恢复直接产生 `value_block`／`block_result` AST，不创建函数或闭包，不改变变量的词法所有者。
块体身份只能引用一次。缺失、重复、循环、未引用的块体及错误的引用种类均须拒绝。
这些语义标记保存在像素中，不依赖文本、AST 或字节码附件。

当前编译器直接写入并恢复这些区域；值块的语义见[枚举与 match](../language/enums.md)。
