# PixelLang 是什么

[简体中文](product.md) · [English](../en/product.md) · [文档首页](README.md)

PixelLang 是一门静态类型的空间编程语言。文本用于编写程序，语义像素 PNG 用于交付和恢复，VS Code Studio 用于编辑、调试与观察状态。

## 核心能力

| 能力 | 使用场景 |
| --- | --- |
| 普通值、泛型、枚举与闭包 | 算法、多文件程序与类型化数据处理 |
| 原生空间类型 | 三维邻域、坐标变换、实体与带权连接 |
| flow 原子状态转移 | 订单状态、控制器与逐步传播 |
| 可执行 PNG | 携带入口及可达模块，恢复可编辑项目 |
| 调试与回放 | 检查来源、变量、历史状态和记录的文件效果 |

## 程序如何交付

编写 `.pxl` → 检查与测试 → 导出 PNG → 提供独立输入执行 → 恢复源码。
PNG 的精确颜色、区域和连接承载程序结构，不通过 OCR 识别文本，也不在元数据中藏入可执行源码或字节码。
文本可以直接编译，无须经过图片。恢复保持程序含义，不保证注释和排版一致。

## 空间与时间

XYZ 是参与计算的三维空间坐标。逻辑时间 T 是显式输入或执行历史；相机、缩放和图布局只是视图。
`fn` 负责普通计算，`flow` 负责持久状态与原子提交，事件调度由宿主或库负责。
三维能力不要求以三维模型文件交付程序，也不要求所有算法都使用空间类型。

## 当前边界

- 项目处于开发预览，语法、协议和包格式允许不兼容变更。
- 编译器用 PixelLang 编写，CLI 与 Studio 默认调用原生编译器；Python 承担用户程序执行、服务和调试回放。
- 工具链需要匹配平台的编译器包；[安装指南](guides/installation.md)区分已有 wheel 与首次源码准备。
- 本地依赖显式声明并锁定；没有网络包注册表或语言级网络 I/O。
- PNG 必须保持精确像素。程序输入、授权数据目录和运行时不属于图片载荷。
- 原生代码生成器用于编译器及验证；常规应用开发与调试以 PixelVM 为运行环境。
