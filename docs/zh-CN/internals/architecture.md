# 编译器架构

[简体中文](architecture.md) · [English](../../en/internals/architecture.md) · [文档首页](../README.md)

CLI 与 Studio 共享同一套 PixelLang 编译器。宿主负责进程、传输和工具集成，语言规则由自举源码实现。

## 编译路径

```text
CLI / VS Code Studio
        ↓
CompilerClient → CompilerWorker → CompilerService
                                      ↓
                          原生 PixelLang 编译器
                                      ↓
                      解析 → 绑定 → 类型 → 特化
                                      ↓
                           帧规划 → IR → 字节码
```

文本路径直接解析 `.pxl`。图片路径从精确像素恢复模块和语法，再进入相同的检查与降低流程。
原生可执行文件、字节码、源码映射和清单必须匹配；普通请求不重新自举，也不回退到旧 Python 编译前端。

## 会话与增量

原生常驻会话保存解析、绑定、声明类型、函数语义、帧与 IR 查询。稳定声明身份和语义依赖决定复用，
源码范围与运行身份重定位到当前项目。失败请求不发布部分结果；容量淘汰只影响性能。
全局声明索引、约束验证和特化仍有全项目阶段。字段和失效规则见[编译服务](../reference/compiler-service.md)。

## 执行与工具

Python PixelVM 执行用户字节码并提供调试、文件授权、检查点和回放；原生运行时也用于编译器与差分验证。
编辑器的解析、类型和引用索引来自原生编译器。宿主将 Unicode 标量范围映射为 VS Code 编辑范围，
应用编辑前重新校验源码快照。职责划分见[Python 边界](python.md)。

## 表示边界

| 表示 | 职责 |
| --- | --- |
| 文本／语义像素 | 可编辑、可恢复的程序源码 |
| AST／类型计划 | 声明、绑定、类型、空间与状态语义 |
| IR／字节码 | 控制流、值操作、源码位置与执行入口 |
| 运行状态／时间记录 | 输入、堆、实例、检查点及外部效果记录 |
| Studio 视图 | 源码投影、空间画布和历史浏览 |

空间 XYZ 与逻辑时间独立。PNG 是二维编码容器，不限制程序的原生三维语义。
接口细节见[编译器接口](compiler-interfaces.md)，正确性要求见[一致性验证](../contributing/conformance.md)。
