# 值存储与访问实现

[简体中文](value-storage.md) · [English](../../en/internals/value-storage.md) · [文档首页](../README.md)

值隔离是语言承诺，结构共享是实现策略。本页说明存储、更新路径、访问权限与快照如何配合。

## 一套访问规则

普通记录、数组、映射和枚举采用值语义。`let` 不可修改；`var` 可以修改自己的字段与元素。
赋值、传参、返回以及按值捕获不得产生可观察的共享修改。读取 `Box[T]` 的字段或 `[T]`
的元素仍得到 `T`，不再引入 `Frozen[T]` 这类权限投影类型。

普通参数只读。需要写回调用者时使用 `inout`，调用处显式写 `&`。
可写访问不能逃逸、进入容器或被闭包捕获。访问从实参求值开始到调用返回保持独占；
当前实现以整个根绑定为单位拒绝重叠写入。较早实参中的嵌套调用可以先完成，
不能因为后续参数将借用同一变量而错误地拒绝它。

普通值不支持任意可变引用环。实体与连接用显式身份表示图中的环；活跃 flow 句柄
引用运行实例，复制句柄不创建新实例。空间快照及历史数据仍保持值隔离。

## 结构共享与更新

值隔离不要求每次赋值都深复制。运行时可以共享不可变存储，在更新时只复制受影响的路径。
当前数组采用持久化向量，映射采用哈希树与稳定迭代顺序；更新后保留旧值供快照和回放使用。
记录字段与嵌套下标更新通过同一条值更新路径写回根绑定。

新语义不要求用户显式冻结或解冻。检查器、字节码验证和运行时共同保证：

- 本地更新不能绕过只读绑定或普通参数权限。
- 显式参数写回不能获得其他根绑定的访问权限。
- 闭包保存创建时的值，之后修改外层变量不改变捕获内容。
- 后续状态更新不能改写先前输出、空间快照或历史检查点。

结构共享不等于零分配；复杂度、内存计费和取消仍须成立。验证可以复用已验证的共享分支，
但新条目及变化路径必须继续检查，不能以性能为由跳过类型与资源边界。

持久化数组按仍存活的共享树节点槽位计入堆预算，包括内部指针；同一节点不因多个数组版本引用而重复计费。垃圾回收在最后一个存储所有者释放节点时扣除费用，恢复检查点时重建存储身份表。普通容器和映射仍保守地按各容器条目计费。对象数与堆上限保持有效，分配失败不得发布部分更新。

## 编译器内部使用

编译器自身也使用相同规则。局部构建器使用普通值集合与显式 `inout`，发布时直接返回值。
将可变上下文拆分为独立的数据所有者时，必须检查此前依赖的别名：

- 修改上下文持有的计划后，返回上下文中的最新计划，而非构造上下文前的旧副本。
- 修改数组中的记录时，显式写回数组元素；修改循环变量不会自动更新数组。
- 完成状态初值和类型信息后再发布结果，不能依赖后续共享修改补齐结果。
- 递归检查、高阶回调和异常诊断必须保留显式写回及正确的源码位置。

中央类型存储及其调用方已合入值语义迁移：类型分析、检查与实例规划分别返回自己完成的结果，
后端需要扩展类型表时显式写回计划。只读查询不取得写权限；需要新生成类型的查询先完成
生成操作，再读取更新后的表，避免参数求值时保存旧快照。

编译器与运行时不保留旧权限类型或冻结／解冻转换；同名用户声明遵循普通名称解析。

## 验证边界

验证需要覆盖普通赋值、嵌套更新、函数边界、回调、泛型、错误路径、空间状态与历史快照。
源码与 PNG 恢复后必须检查同一契约；自编译固定点必须使用相同的完整源码快照。
单个内部模块的类型检查或快照测试不能替代生成编译器、完整 PNG 与 Studio 验收。

性能验证分别测量编译、值更新、图状态和 PNG 导出／恢复。并发开发测试的耗时仅用于
定位问题，最终对照须遵循[性能验证](../contributing/performance.md)的电源、缓存与负载条件。
